Back up your live master before you import anything. ==================================================================== WHY THIS TOOL EXISTS (the real P6 problem) ------------------------------------------ You send your programme out to subcontractors; they send monthly updates back as XER files. Here is the danger, straight from Oracle's own import rules: when you import a contractor's XER, the DEFAULT action for "Relationships to External Projects" is *Update Existing*, which ADDS the contractor's links to other projects — including links into YOUR master — into your database. So a single rogue or copied link inside a contractor file can silently re-wire your master's critical path and float the moment you import it. You cannot trust the file. You must verify, before importing, that it will not create, change, duplicate or overwrite anything in your master. That is exactly what Logic-Guard does — 100% offline, nothing leaves your PC. THE WORDS YOU'LL SEE (glossary) ------------------------------- • Master – your main/head programme; the one you protect. • Contract / Sub – a subcontractor or package programme. • Tie / Relationship / Link – a logic link (predecessor -> successor). • TASKPRED – the table inside an XER that stores the links. • Short name – the project name INSIDE the XER (e.g. PROJECT_A), NOT the file name (PROJECT_A_RevA.xer). • Interface / CM – an agreed hand-over point between master and a contract (often coded CM-01, CM-02 ...). • External Dates – hidden constraint dates P6 bakes onto activities when a linked project wasn't present at import. • Audit ID – one ID stamped on the Excel AND the cleaned package so the pair can be proven to match. THE FOUR FLAGS (colours + what they mean for YOUR master) --------------------------------------------------------- • Extra (red) – a tie from a received file that reaches INTO your master. Importing it WILL add/alter logic in your master. Worst kind: a link into a master INTERNAL activity (not an agreed CM interface). • Suspected Copy (amber) – the SAME Activity ID appears in more than one project. If it clashes with a MASTER ID it can OVERWRITE your master activity on import. FIX by RENAMING in P6 — this is never auto-removed, because deleting a link cannot fix a duplicate ID. • Orphan (grey) – a link points at a project that is NOT loaded (deleted/renamed, or a file you forgot to load). • Approved (green)– the master's own internal logic, or an interface you have formally signed off in the safe list. WHY A FLAG CAN SHOW ZERO (and that's GOOD) ------------------------------------------ Suspected Copy 0 = all IDs unique. Orphan 0 = every link points at a loaded project. Extra 0 = nothing reaches into your master. All green means SAFE TO IMPORT — that's the goal, not a fault. If you EXPECTED problems and see none: did you load the received files, is the master short name right (blue button), and did you load the master WITH them? TWO LINKS BETWEEN THE SAME PAIR (FS + SS) ----------------------------------------- Schedulers often deliberately put two relationships between the same two activities (e.g. a Start-to-Start plus a Finish-to-Finish). The cleaner removes only the exact link that was flagged (it matches on the relationship TYPE too), so a legitimate second link between the same pair is never taken out by mistake. EXTERNAL DATES — a P6 thing this tool CANNOT see (important) ------------------------------------------------------------ When a contractor imported a project that linked to YOUR master but WITHOUT your master present, P6 can bake those links onto activities as "External Early Start" / "External Late Finish" DATES. These behave like constraints, not TASKPRED links, so NO XER tool can detect or strip them. After importing a cleaned file, in P6: 1. Add columns "External Early Start" and "External Late Finish". 2. Any value there is a hidden external date from a prior import. 3. Clear it if it is not agreed, then reschedule (F9). 4. Re-check your master's critical path. Logic-Guard removes the rogue LINKS; you clear leftover external DATES in P6. Do both and your master is clean.
